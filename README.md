# FABLEBRINK

**Build beyond the known.**

FABLEBRINK is a code-first 2D pixel sandbox prototype for Android landscape and desktop. The world is drawn procedurally from GDScript; there are no downloaded background-art packs or sprite sheets. The game world is rendered with code-drawn primitives. The launcher icon is generated by `tools/generate_icon.py`; no third-party artwork or sprite pack is included.

## What's in this repository

### Game client
- Godot 4.7.2, GDScript, 1280×720 landscape-first layout.
- Startup splash, separate Login and Create Account screens.
- Unique username registration; passwords are hashed on the server with Node.js `scrypt`.
- Main menu: Play, Multiplayer, Settings, About, Log Out, Exit.
- Local world creation, world names, deterministic generated terrain and local autosave.
- Side-view sandbox prototype: walking, low jump, grass/dirt/stone, trees, houses, clouds, sun, mining duration, visible drop pickups, block placement and a starter pickaxe.
- Inventory popup and counters, Hi / Sad / Happy emotes, username nameplates.
- Android virtual joystick plus Jump / Mine / Place buttons; desktop A/D or arrows, W/Space to jump, F to mine and G to place.
- Compact room chat panel and short chat notifications.

### Online server
- Node.js 22 + WebSocket (`ws`); no Firebase and no third-party Godot networking addon.
- Host / Join with random 6-character room codes.
- Five-player room cap. The host may start with fewer than five players.
- Joining is allowed only while the room is in `lobby` state. Starting the game changes the room to `playing`; the same code is rejected as `ROOM EXPIRED` for new joins.
- Separate errors for invalid code, full room, expired room, and unavailable server.
- Realtime movement snapshots, emotes, room chat and block-change relay.
- PostgreSQL support through `DATABASE_URL`; local JSON storage is available for development only.

## Current scope: prototype, not a finished commercial game

This ZIP gives you a coherent, expandable vertical slice. It is not honest to call every long-term feature finished yet. In particular, the current build does **not** include NPC dialogue quests, enemies/bosses, combat, private messages, cross-device singleplayer cloud saves, reconnect/resume, or server-authoritative physics and anti-cheat. Multiplayer inventory is still local to each client; a remote player's block-drop effect is visual only, not a shared collectible. Multiplayer rooms are intentionally limited to five players and are held in server memory. If the server restarts, active rooms end. The generated world is a large bounded map (4,800 tiles wide), not an infinite Minecraft-style world.

The client needs a deployed WebSocket server before online registration and multiplayer can work. A source ZIP or GitHub Actions build cannot itself host a 24/7 game server.

## Build the Android APK from GitHub (phone-friendly)

For a step-by-step Indonesian guide, see [MULAI_DI_HP.md](MULAI_DI_HP.md).

1. Create a **public** GitHub repository named `FABLEBRINK` (or another name you prefer).
2. Upload the contents of this ZIP to the repository root. Do not upload the outer ZIP as a single file; extract it first so `project.godot` is at the repository root.
3. Open **Actions** in the repository and run **Build FABLEBRINK Android APK**, or push a change to `main` / `master`.
4. When the workflow succeeds, open the run, scroll to **Artifacts**, and download `FABLEBRINK-Android-debug`.
5. Extract the artifact ZIP to get `FABLEBRINK-debug.apk`.

The workflow uses Godot 4.7.2 stable, its official export templates, Java 17 and Android SDK packages. It produces a **debug-signed APK** for testing. The workflow creates a temporary debug keystore on the GitHub runner; it is not a permanent release key and is never committed to the repository. A release-signed APK requires your own securely stored signing key.

If the export fails, open the failed Actions run and read the first actual `ERROR:` line. A warning alone is not necessarily a build failure.

## Deploy the realtime server without a PC

The client and server are separate. You can configure the server from the game's Login screen or Settings screen by entering its WebSocket URL.

### 1. Create a PostgreSQL database

The server supports any PostgreSQL provider that supplies a connection string. Neon currently lists a $0 Free plan with usage limits (including 1 GB project storage, 100 compute-unit hours per project per month, and scale-to-zero after inactivity). Free quotas and provider policies can change; check the provider's current plan before relying on it.

Copy the **pooled** PostgreSQL connection string from your database dashboard. Keep it private.

### 2. Deploy the server

This repository includes a root `render.yaml` for a Render Web Service using the `server/Dockerfile`.

1. Upload the project to GitHub first.
2. In Render, create a new **Blueprint** from that repository.
3. When prompted for `DATABASE_URL`, paste the PostgreSQL connection string. Keep `DATABASE_SSL=true`.
4. Wait for the service deployment to complete. Open `https://YOUR-SERVICE.onrender.com/health`; the response should contain `"status":"ok"`.
5. Your game WebSocket URL is `wss://YOUR-SERVICE.onrender.com/ws`.
6. Enter that URL on the game's Login screen and create an account.

Render Free services can spin down when idle, restart, and have an ephemeral filesystem. The game client sends a small heartbeat while connected to help keep an active room awake, but this does not guarantee uninterrupted uptime. Use PostgreSQL for account persistence; do not rely on the server's local JSON file on an ephemeral host. Free hosting is suitable for a small test, not a production uptime promise.

### Local server (optional)

On a machine that has Node.js 22 or newer:

```bash
cd server
npm install
npm start
```

Local development uses `server/data/accounts.json` if `DATABASE_URL` is not set. For local devices on the same network, set the client URL to `ws://LAN-IP:8080/ws`. For internet multiplayer, use a publicly reachable TLS endpoint (`wss://`).

## Game controls

| Action | Desktop | Android |
|---|---|---|
| Move | A / D or ← / → | Virtual joystick |
| Jump | W / ↑ / Space | JUMP |
| Mine | Hold F | Hold MINE |
| Place dirt | Hold G | Hold PLACE |
| Chat | CHAT button | CHAT button |
| Emote | HI / SAD / HAPPY buttons | HI / SAD / HAPPY buttons |

The starter character has a basic pickaxe, so stone can be mined after holding the mining control for longer than dirt. Breaking grass/dirt/wood awards a matching material in this prototype. Place currently uses dirt from the inventory.

## Security notes

- Passwords never travel in the APK source or get written to game save files. The game sends credentials over the WebSocket connection; use `wss://` for internet deployment.
- The server stores only a random salt and a `scrypt` password hash, not plaintext passwords.
- Do not expose `DATABASE_URL` in client files or commit it to GitHub.
- This is a small prototype server. Before a public release, add account recovery, abuse moderation, stricter per-IP throttling, authoritative movement/block validation, backups, monitoring and a privacy policy.
